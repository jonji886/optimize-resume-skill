# ATS Coverage

只负责「机器能不能正确解析和检索」。位置与可读性属于
`recruiter-review.md`（Recruiter Salience），两者必须分开检查。

## 检查项

| 检查项 | 说明 |
|---|---|
| JD 核心关键词覆盖 | `jd.core_requirements` 中每一项，简历中是否有对应且真实的词 |
| 技能可解析 | 技术名词、产品名、平台名是否使用行业通用写法 |
| 职责名词可解析 | 岗位相关职责是否用了目标岗位的通用说法 |
| 职位名称 | 目标岗位名称是否清晰，文件命名是否包含岗位名称 |
| 学历可解析 | 学历、专业、时间是否结构化写出 |
| 证书可解析 | 已确认的证书是否写明全称 |
| 格式机器友好 | 纯 Markdown、无文本框、无图片化文字、无表格承载关键信息 |
| 同义词缺失 | 是否存在「意思对但关键词完全缺失」的情况 |

`validate_claims.py` 会输出两类结果：

- `ATS_KEYWORD_MISSING`：事实支持该关键词，但简历中完全没有出现；
- `ATS_KEYWORD_UNSUPPORTED`：简历出现该关键词，但没有任何事实支持。

两者都是 **warning**：它们影响可检索性，不属于事实安全违规。

## 关键词复现规则

- 优先复现真实的技术名词、产品名、行业词和职责名词；
- 使用事实支持的原词，不为了凑词而改写事实；
- 不要为了原词复现堆砌动词；
- 不要把 JD 的「负责」机械改写成候选人的「主导」。

~~~text
JD:      支付 API 集成
事实:     复杂 OpenAPI 接入与系统集成（非支付场景）
错误:     具备支付 API 项目经验
正确:     具备复杂 OpenAPI 接入与系统集成经验，可迁移至支付 API 场景
~~~

## 禁止

- Keyword Stuffing：把关键词堆成技能清单，或在同一句里塞入多个无关名词；
- 新增未经确认的技术栈，只为让关键词出现；
- 为了覆盖关键词而恢复独立的「核心技能」模块；
- 通过同义词替换把无证据能力写进简历。

ATS 优化必须建立在 **事实支持 + 自然表达** 之上。

## 失败时如何处理

| 情况 | 处理 |
|---|---|
| 事实支持但关键词缺失 | 在相关经历中自然补上真实原词，优先放在最相关的 bullet |
| 关键词天然不可能出现在该事实中 | 保留事实表达，在交付说明中标注为 ATS 风险 |
| 无事实支持 | 不写。列入「面试需准备的缺口」 |
| 关键词存在但埋得很深 | 属于 Recruiter Salience 问题，见 `recruiter-review.md` |
