# 内容筛选与优先级

决定「保留 / 前置 / 压缩 / 合并 / 删除」时阅读。

## Layer 1：快速分类

对每条经历和 bullet 做第一层分类：

| 分值 | 含义 | 默认动作 |
|---|---|---|
| 2 | 直接证明 JD 核心要求 | KEEP_AND_PRIORITIZE |
| 1 | 证明可迁移能力 | KEEP 或 COMPRESS |
| 0 | 与目标岗位无关 | REMOVE |

这一层只用于快速分流，不要直接据此定稿。

## Layer 2：优先级评分

对 Layer 1 中得 1–2 分的内容，再按下列维度排序。
只是帮助排序的启发式，不需要精确数值，也不需要展示给用户。

| 维度 | 判断问题 |
|---|---|
| JD Relevance | 这条内容回应了 JD 的哪一条要求？ |
| Evidence Strength | 有具体对象、动作、技术细节，还是只有概括？ |
| Impact | 有可验证的结果、规模、上线状态或交付物吗？ |
| Interview Defensibility | 面试官追问细节时，候选人能答到什么深度？ |
| Information Uniqueness | 这条内容是否提供了别处没有的信息？ |
| Recency（可选） | 是否属于最近一段相关经历？ |
| Role Importance（可选） | 在原岗位中是否属于主要职责？ |

排序直觉：**Evidence Strength > Impact > Recency**。
一条可自证的细节，胜过三条概括性的「负责 XX」。

## Information Uniqueness

这是最容易失控的一项。以下都是同一能力被重复证明：

- 个人优势写「5 年 ToB 技术交付经验」，工作经历又用多条 bullet 重复同一概括；
- 工作经历与项目经历都在讲 API 集成；
- 多个 bullet 都在讲「跨团队协作」；
- 不同项目用相同措辞描述「方案设计 → 联调 → 上线」。

如果两条内容证明的是同一个能力，保留唯一更强的那条：

1. Evidence 更强；
2. Impact 更大；
3. 更符合目标 JD；
4. 更容易被面试验证。

另一条 `REMOVE` 或 `COMPRESS`。
`validate_claims.py` 的 `RESUME_DUPLICATE_BULLET` / `CLAIM_DUPLICATE_TEXT` 会捕获
措辞高度重复的情况。

## 一次选择，局部复核

内容筛选只做一次主要 Evidence Selection：一种核心能力原则上保留一个主要 Evidence；
其他位置只有在提供明显新增信息时才保留。个人优势可以给结论，工作经历可以给具体过程，
这类层级差异不自动等于重复。

完成选择后直接写完整初稿，再运行 deterministic validator。不要在写每条 bullet 时两两
比较全部 claims、估算 similarity threshold，或为了追求全局最优不断回到筛选阶段。若 validator
真实返回 duplicate warning，只定位受影响的 bullet / claim，局部合并或压缩一次；若只是合理
的「结论 + 证据」层级重复，可以保留并记录为 non-blocking warning。

## 五种动作

| 动作 | 使用条件 |
|---|---|
| `KEEP_AND_PRIORITIZE` | 直接匹配 JD 核心要求，且 Evidence 强 → 前置到个人优势或最近相关经历 |
| `KEEP` | 相关但不需要前置 |
| `COMPRESS` | 相关但 Evidence 弱、或与更强内容部分重叠 → 压成 1 条或 1 句话 |
| `MERGE` | 多条证明同一能力 → 合成一条信息量更高的表述 |
| `REMOVE` | 与 JD 无关，或只重复已有信息 |

## 具体规则

- 项目不强求数量，通常保留 1–3 个最相关项目。
- 弱相关个人项目不得仅因包含 AI 关键词而占用版面。
- 个人优势写「能力结论 + 证据或规模」，不复述完整工作过程。
- 不单独设置「核心技能」模块；技术、工具和业务方法结合具体工作或项目证据
  写入对应 bullet。
- 与岗位无关的内容压缩或删除，而不是为了「丰富简历」保留。

## 项目背景取舍

不要将「背景可不加关键字」理解为「背景默认删除」。逐个项目判断：

- 保留能说明客户痛点、业务场景、项目目标或方案必要性的背景，通常压缩为 1 句话；
- 删除空泛的行业介绍、与后文重复的背景，或无法帮助理解项目价值的背景；
- 项目背景应服务于后续的方案设计、POC、交付动作和结果，
  避免只写「客户希望数字化」这类泛化表述；
- 背景是最终简历内容，不属于内部注释，也不受「每个项目 2–3 条 bullet」限制；
  篇幅不足时优先压缩动作描述，不要机械删除有证据价值的背景。

## 与事实安全的边界

内容筛选只决定「写不写、写多少、放哪里」，不改变事实。
任何为了提升匹配度而把 `support` 写成 `lead`、把 `unknown` 写成已知的做法，
都违反 `fact-boundaries.md` 与 `scope-rules.md`。
