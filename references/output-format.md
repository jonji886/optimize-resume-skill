# 输出结构与格式

排版或写文件前阅读。`scripts/lint_resume.py` 按本文档执行格式检查。

## 模板

~~~markdown
# 姓名
手机/微信：xxx ｜邮箱：xxx
## 个人优势
- **关键字**：能力结论 + 证据或规模。
## 工作经历
### 公司｜职位
时间
- **关键字**：动作 + 场景 + 结果或价值。
## 项目经历
### 项目｜角色
时间
- **关键字**：动作 + 场景 + 结果或验证。
## 教育背景与认证
- 学校｜专业｜学历｜时间
- 已确认的认证
~~~

`## 项目经历` 可选；`## 个人优势`、`## 工作经历`、`## 教育背景与认证` 为必需章节。

## 格式规则

- 顶部不写求职意向、工作经验、城市、性别、年龄或籍贯；
- 个人优势控制在 3–4 条，每条不超过 2 行；
- 工作经历每条必须使用「**关键字**：内容」，关键字通常 4–8 个字且同一经历中不重复；
- 项目经历建议使用相同格式；若背景能解释业务痛点、项目目标或方案必要性，
  应保留为 1 句话且可不加关键字；
- 工作经历按倒序排列，每段通常 3–6 条；
- 项目经历通常 1–3 个，每个 2–3 条；
- 不单独设置「核心技能」模块；技术、工具和业务方法写入相关工作或项目经历；
  教育背景与认证合并为一个章节；
- 章节顺序为：个人优势 → 工作经历 → 项目经历 → 教育背景与认证。

## 文件命名

- 输出文件命名为「姓名-{岗位名称}.md」，去除公司和城市前缀；
- Fact Store 使用同名 sidecar：`姓名-{岗位名称}.facts.yaml`；
- 修改现有目标简历时更新原文件，不额外创建「最终版」「优化版」等重复文件。

## 禁止

- 最终文件中出现 TODO、scope 注释、HTML 注释或其他内部标记；
- 旧的【标签】格式；
- 重复 bullet 或重复章节；
- 空 section。

## 校验

~~~bash
python3 scripts/lint_resume.py "/绝对路径/姓名-{岗位名称}.md"
~~~

脚本只检查输出结构、Markdown 格式、重复、空 section、TODO 和长度类问题。
事实安全由 `scripts/validate_claims.py` 检查，两者不重叠。
